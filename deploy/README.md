# Deploy Guide: DigitalOcean VPS Without GPU

This guide describes a simple production-style deployment for this project on a
small VPS, intended for a few people to view and test the simulator over the
network.

The current `Dockerfile` is a development container. For a public deployment,
prefer a dedicated `Dockerfile.prod` plus a small reverse-proxy setup.

Target shape:

```text
Internet
  -> HTTPS/WSS reverse proxy (Caddy)
  -> web simulator frontend
  -> rosbridge websocket on localhost/internal network
  -> ROS 2 launch processes
```

No NVIDIA/GPU support is required.

---

## Recommended Provider

Use DigitalOcean for this use case:

- Standard CPU Droplet
- Ubuntu 22.04 or 24.04
- 2 vCPU / 4 GB RAM minimum recommendation
- 50 GB disk or more if building images on the VPS
- No GPU

AWS EC2 also works, but DigitalOcean is simpler for a small demo because there
is less networking/IAM/VPC overhead.

---

## Important Security Notes

Do not expose rosbridge directly to the public internet without protection.

Preferred public surface:

```text
https://your-domain.example
wss://your-domain.example/rosbridge
```

The reverse proxy should forward `/rosbridge` to an internal `localhost:9090`
or Docker-network-only rosbridge endpoint.

For a private demo, add at least one protection layer:

- Caddy/Nginx Basic Auth
- firewall allowlist for known IPs
- Tailscale/WireGuard VPN
- application-level auth in front of the frontend/proxy

## Step 1: Create The VPS

1. Create a DigitalOcean Droplet:
   - Image: Ubuntu 22.04 LTS or Ubuntu 24.04 LTS
   - Size: 2 vCPU / 4 GB RAM
   - Region close to the users
   - Authentication: SSH key

2. Point DNS to the Droplet:

```text
A     your-domain.example     <droplet-public-ip>
```

3. SSH into the server:

```bash
ssh root@your-domain.example
```

---

## Step 2: Basic Server Setup

Update packages:

```bash
apt update
apt upgrade -y
```

Create a deploy user:

```bash
adduser deploy
usermod -aG sudo deploy
```

Copy your SSH key to the new user or configure it manually:

```bash
mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
```

Log in as deploy:

```bash
ssh deploy@your-domain.example
```

## Step 3: Install Docker

Install Docker using the official convenience script:

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker "$USER"
newgrp docker
docker run hello-world
```

Docker Compose is included with recent Docker installs:

```bash
docker compose version
```

## Step 5: Add Production Docker Files

Create these production files in the repository:

```text
Dockerfile.prod
compose.prod.yml
Caddyfile
```

Use `deploy/DockerfileProdAgentPrompt.md` to generate `Dockerfile.prod` in a
follow-up implementation step.

Recommended production layout:

```text
services:
  app:
    builds frontend assets
    serves static app or runs a small HTTP server

  ros:
    runs ROS 2 launch file(s) and rosbridge

  caddy:
    terminates TLS
    proxies frontend and /rosbridge websocket
```

For the first deployment, it is acceptable to use one app/ROS image if that is
simpler. Keep it CPU-only.

---

## Step 6: Environment Variables

The browser must connect to rosbridge through the public HTTPS domain using WSS:

```text
VITE_ROSBRIDGE_URL=wss://your-domain.example/rosbridge
```

Do not hardcode `ws://localhost:9090` for public deployments.

Keep local/dev `.env.local` separate from production env.

---

## Step 7: Reverse Proxy With Caddy

Example `Caddyfile`:

```caddyfile
your-domain.example {
  encode gzip

  # Optional but recommended for small private demos.
  # Replace the hash with one generated by:
  # caddy hash-password --plaintext 'your-password'
  # basicauth {
  #   demo-user <hashed-password>
  # }

  handle_path /rosbridge* {
    reverse_proxy ros:9090
  }

  handle {
    reverse_proxy app:80
  }
}
```

Notes:

- Caddy automatically obtains and renews TLS certificates.
- `/rosbridge` must support WebSocket upgrade; Caddy handles this automatically.
- The `ros` service should not publish port `9090` publicly; expose it only on
  the Docker network.

## Step 8: Compose Production Stack

Example `compose.prod.yml` outline:

```yaml
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.prod
      target: app
      args:
        VITE_ROSBRIDGE_URL: wss://your-domain.example/rosbridge
    restart: unless-stopped

  ros:
    build:
      context: .
      dockerfile: Dockerfile.prod
      target: ros
    restart: unless-stopped
    command: >
      bash -lc "source /opt/ros/$ROS_DISTRO/setup.bash
      && source /home/ros/ros2_ws/install/setup.bash
      && ros2 launch angy_sim_topics web_test.launch.py"

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - app
      - ros

volumes:
  caddy_data:
  caddy_config:
```

Adjust the ROS launch command to match the package/launch file you want to
serve in the demo.

## Step 9: Build And Start

```bash
docker compose -f compose.prod.yml build
docker compose -f compose.prod.yml up -d
```

Check containers:

```bash
docker compose -f compose.prod.yml ps
docker compose -f compose.prod.yml logs -f
```

Open:

```text
https://your-domain.example
```

---

## Step 10: Firewall

Allow only SSH, HTTP, and HTTPS:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

Do not allow public `9090/tcp` unless you deliberately want rosbridge exposed.

---

## Step 11: Smoke Test

From your local browser:

1. Open `https://your-domain.example`.
2. Confirm the app loads.
3. Confirm the configured rosbridge URL is `wss://your-domain.example/rosbridge`.
4. Connect.
5. Open the ROS2 topics panel.
6. Confirm topics are discovered.
7. Render a supported topic.
8. Confirm echo works only when expected.

On the server:

```bash
docker compose -f compose.prod.yml logs -f ros
docker compose -f compose.prod.yml logs -f app
docker compose -f compose.prod.yml logs -f caddy
```


## Operational Notes

- This is a single shared simulator instance. Multiple users see/control the
  same backend.
- For independent per-user sessions, add a session manager or run separate
  stacks per user.
- ROS2 + Node + Docker layers can consume disk quickly; monitor disk usage:

```bash
df -h
docker system df
```

- If builds fail with apt cache/disk errors, increase Droplet disk size or prune
  Docker/cache:

```bash
docker system prune -af
sudo apt clean
```

## Production Checklist

- [ ] `Dockerfile.prod` exists and does not require host UID/GID args.
- [ ] Frontend uses `wss://your-domain.example/rosbridge`.
- [ ] rosbridge is only reachable through reverse proxy or VPN.
- [ ] Caddy/Nginx terminates TLS.
- [ ] Firewall does not expose port `9090`.
- [ ] Basic Auth/VPN/IP allowlist is enabled for private demos.
- [ ] `docker compose -f compose.prod.yml up -d` starts cleanly.
- [ ] Browser can connect and discover topics.
